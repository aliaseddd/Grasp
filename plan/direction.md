# Grasp's direction: the plan cut to what it is for

This is the step after [`extensibility-strategies.md`](extensibility-strategies.md). That document asked how Grasp's architecture should grow to take all 620 of SysON's features, one hand-written HTML file at a time. On November 8, 2026, Damon reframed the goal, and this document cuts the plan to it. [`scope.md`](scope.md) sorts the 620 entries and the 23 strategies by what they serve under the cut, and [`spikes/`](spikes/) holds the experiments this document rests on.

## What Grasp is for

Damon's words, confirmed point by point:

- The tool is unpleasant to use. The header, with its Add palette and its row of buttons, is the wrong design. Nothing can be resized: the side panel is fixed and can only be hidden, and frames and boxes have no handles. Every view sits on one plane; it needs tabs, each tab a plane of its own.
- What Damon wants is a mature look and feel. SysON's workbench is the reference, but any such workbench would do; the architecture change was only ever a means to that end. He does not need a mature tool: not SysON's feature set, not the 23 strategies for their own sake.
- He needs four things. Read and write textual SysML v2. Hold, show and edit every KerML and SysML v2 concept, KerML as far as SysML v2 stands on it. Let Claude read and change the diagrams themselves, not only the model behind them. Keep code in GitHub, written by Claude alone, reviewed by Damon, pushed when approved, and linked from the elements it realizes.
- Three constraints changed. One HTML file is no longer required. Nothing can be installed on the workplace machine, no installers, no compilers, but files can be downloaded, so libraries vendored as files are fine. The page may keep its files on disk. Two stay: the page opens from the file system in a Chromium browser with no server, and Claude's side of the loop reads and writes the same files; the page's store on claude.ai drops out.

## What that changes

The strategies document's premise was one hand-written page with no libraries: twenty-three ways to turn its shared code into tables so that features could be added in folders of their own. With vendored libraries allowed, the look and feel Damon wants is the thing libraries are best at, and the hardest need, reading SysML v2, has a ready-made answer that did not exist when the premise was set. So the page is rebuilt on libraries, and Grasp's own code narrows to what no library knows: the model, its rules, its files and its exchange with Claude.

## What was checked

Everything below was read from a primary source or run in this session; `spikes/README.md` says how to run the experiments again.

**What a page opened from disk can do.** In Chromium 153, a page at a `file://` URL is a secure context, and `showDirectoryPicker`, `showOpenFilePicker` and `showSaveFilePicker` exist, so the File System Access API is there to open a folder and write files back. Classic `<script src>`, stylesheets and images load; localStorage and IndexedDB work; a request to api.github.com passes CORS and its answer is readable (GitHub allows an unauthenticated page 60 requests an hour; with a token, far more). Module scripts, dynamic `import()`, `fetch` and XMLHttpRequest of a file beside the page, and a Worker made from a file are all blocked ("Cross origin requests are only supported for protocol schemes: chrome, chrome-untrusted, data, http, https"); a Worker made from a Blob URL works, provided its code is inlined or posted to it, since it cannot import a file beside the page either. So a multi-file page carries its JavaScript as classic scripts bundled ahead of time, and anything it needs as data, libraries and the parser included, comes inside a script or through a folder the user picked. Edge and Chrome let an administrator restrict the File System Access API by policy: a default guard setting of "block" disables all three pickers for every site, and a page opened from disk can be targeted only wholesale, through the pattern `file:///*`; unset, the user is asked at each request. A separate policy, AllowFileSelectionDialogs set to disabled, suppresses every file dialog, the pickers and `<input type=file>` alike. So saving must also work as a download, which needs no dialog, and where even opening is blocked the files pass through the conversation.

**Damon's machine (November 12).** A single self-contained probe page, `grasp-probe.html`, was opened from disk in Chrome 157 on Damon's work machine (Windows, 20 cores, 16 GB), after a baseline run in Chromium 153 on Claude's side whose results matched. Today's page, `canvas/index.html` from the extracted repository, opens, and Download state and Import state both work. The page is a secure context with all three pickers present; a folder picked, written to and read back works; the remembered folder handle survived a reload with its permission still `granted`, and Damon confirmed it after a full restart of Chrome too; the save picker, the open picker, the file input and a download all work; `chrome://policy` shows nothing that blocks them. Workers made from a Blob URL, IndexedDB and localStorage work. api.github.com, raw.githubusercontent.com and github.com are all reachable, and a PUT to the GitHub API with an `Authorization` header and an invalid token got GitHub's 401, so the browser's preflight passes; nothing was written, and a real write with a working token is not yet proved. WebAssembly is not blocked and runs compiled: a loop of 50 million steps took 39 ms, against 277 ms in JavaScript. OpenSysML's real module (about 15 MB) was not tried there, so its load and parse times on that machine are unmeasured. The probe is not in the repository; its only copy is the one sent to Damon.

**What SysON is made of.** Sirius Web's diagram package, which SysON's diagrams are, is React 18 with React Flow (`@xyflow/react` 12.10.2) for the diagrams, elkjs 0.11.0 for layout, Material UI 7 for the widgets, `react-resizable-panels` for its three zones, `pathfinding` for edges that go round boxes and `html-to-image` for image export; SysON adds `material-react-table` for its tables and `@mui/x-tree-view` for its explorer. All of it is EPL-2.0 or MIT. SysON itself needs a Java server and PostgreSQL, so it cannot be what Damon opens; its parts can.

**The candidate stack, bundled and opened from disk.** React 18.3.1, `@xyflow/react` 12.10.2, `dockview-react` 8.8.3 (MIT; tabs, groups, draggable sashes, floating panels, no dependencies) and elkjs, bundled by esbuild 0.28.2 into one classic script of 2.2 MB and a stylesheet of 157 KB in half a second. Opened from disk, the page is ready in about 350 ms with no console errors (the spike's own log says 870 ms because it waits half a second before reading): an Explorer panel on the left, a tabbed editor group in the middle ("view1 : GeneralView", "Package1.sysml"), a Details panel on the right, two sashes that drag (one drag widened the Explorer from 220 to 338 px), a diagram of SysML-style nodes with compartments laid out by ELK, eight resize handles on the selected node (a drag of one resized it from 170 by 80 to 200 by 95, on the snap grid), a minimap and zoom controls (`spikes/stack/`). One lesson from the spike itself: fit the view after the layout has placed the nodes, not before, or part of the diagram lands outside the panel. With 5,000 nodes and 5,000 edges the first fitted frame comes about 2 s after the script starts, during which React Flow renders every node once to measure it and blocks the page for about 1.2 s; fitted to the window, all 5,000 nodes and edges stay in the DOM, about 55,000 elements, and a pan runs at 8 to 10 frames a second; at 100% zoom in a 1400 by 820 window about 60 nodes and 1,800 edges are in the DOM, at 200% about 20 nodes and 900 edges, and a pan runs at 35 to 50 frames a second. With 1,000 nodes the first render takes 0.4 s. ELK's bundled build runs on the page's thread, where laying out 300 nodes with compartments and ports freezes the page for about 1.1 s and 1,000 nodes for about 3.3 s; in a worker made from a Blob URL with the worker's source inlined, 1,000 nodes take about 3.1 s with the page's longest stall at 22 ms, so that is how ELK runs. So the new page must do at a far zoom what the old one does below 25%: draw boxes as outlines and leave edges and labels out, or cull edges itself. For comparison, Grasp's scale tests hold a drag move under 16 ms at 5,000 elements in three views; here a 20-step drag or pan took about 18 ms a step with Playwright's event dispatch included.

**maxGraph, the other candidate for the diagrams.** Apache-2.0, the TypeScript successor of mxGraph (draw.io's engine), with an editor built in: move, resize, rotate, connect, orthogonal and Manhattan routing, groups that fold, undo and redo, layouts. It is at 0.25.1 (October 21, 2026) with breaking changes between minor versions, needs a bundler, and draws its own SVG, so nodes would be shapes written in its own terms rather than components. It stays the fallback if React Flow's lack of built-in routing and undo turns out to cost more than this document expects.

**Reading SysML v2: the parsers that exist in November 2026.** Hand-writing a parser for the full grammar, the strategies document's plan, is no longer the best option:

- OpenSysML (OpenMBEE) is "a SysML v2 and KerML 1.1 implementation in Go", Apache-2.0, under active development with nightly builds: parsing, diagnostics, expression evaluation, instantiation, execution, a language server, a REPL, a gRPC service, an MCP server, a Jupyter kernel. It bundles the 94 standard library files of the pilot implementation's 2026-09 release and parses all of them; those files are byte for byte the ones of the 2026-09.1 release `canvas/check.sh` validates with, but the two releases differ in the validator's own code, so the module's verdicts and the pilot's are two opinions, and the plan keeps the pilot as the authority. Against the pilot's example corpus the module agrees diagnostic by diagnostic on 522 of 924 files, a comparison its authors call a demonstration rather than a conformance suite, and it claims no conformance certification. Its npm package `@openmbee/opensysml-wasm` 0.12.1 is a browser build of the same engine: `sysml-wasm.wasm`, 41.0 MB.
- Probed from Node with the module running inline: it connects in about 0.3 s and parses a small package in about 0.1 s; `find('Package1::hosts')` returns the symbol with its kind (`partUsage`), its multiplicity, its typing resolved to `Package1::Host`, its specializations, its attributes including one inherited through that typing (the standard library's own attributes are counted but withheld), and its children; `walk()` lists every symbol with kind and qualified id, but carries no imports, documentation bodies or source positions; the diagnostics are the model's; `renderView` renders a view as a tree with every node's file position and tells apart kinds the walk collapses. A later probe parsed 5,021 symbols in about 1.3 s and walked them in about 2.4 s, at about 405 MB of heap. What the wasm build lacks, by its own capability list: `convert` (to SysML text, KerML, Turtle or the API's JSON), `renderDocument` and `query`; those live in the `sysml-grpc` binary, which could run on Claude's side only (`spikes/opensysml/probe.mjs`).
- The same npm package ships a second module, the browser build of OpenSysML's command line and REPL (64.8 MB, 15.5 MB gzipped), which the typed client does not use. Run under Node with an emulated terminal, it converted Grasp's own example, `docs/sysml/stronghold-proof.sysml` (4.5 KB), into the SysML v2 API's standard JSON element form in 1.6 s: 189 elements, 258 KB, every membership, import, typing, multiplicity, literal, documentation and feature chain an element of its own metaclass, with ids derived from qualified names, so two runs give identical output. It converted that JSON back into 139 lines of text with the comments and documentation in place, and that text converts to the identical set of 189 elements. OpenSysML calls this conversion experimental: it covers model structure and the behaviour bodies state, refuses what it cannot write back, and its vocabulary may change without a compatibility path. The full gRPC service, with conversion, queries, document rendering and source-preserving edits, is a documented WebAssembly build target too, buildable from the Apache-2.0 sources but not published (`plan/spikes/README.md` says how the conversions were run).
- Probed from a page opened from disk, where the module cannot be fetched: gzipped to 10.1 MB and embedded as base64 in a classic script of 13.4 MB beside `wasm_exec.js` and a 297 KB bundle of the client, it decodes, decompresses, compiles and starts in about 0.6 s, and has a parsed, name-resolved model about 0.8 to 0.9 s after the scripts start on this session's machine, a 4-core server; the time scales with the speed of one core (1.5 s with the processor throttled to half, 2.8 s at a quarter), the JavaScript heap is about 90 MB but the browser process grows to 500 to 700 MB, and while it runs inline every parse blocks the page's thread. It caught the mistakes planted in the sample (two definitions named `App`, a port typed by a part def) (`spikes/opensysml/wasm-page.cjs`). Two conditions of Damon's machine matter here: Edge's Enhanced Security Mode runs WebAssembly in a slower, incomplete interpreter, and Chrome's policy that blocks just-in-time compilation removes WebAssembly altogether; a page opened from disk is not a site Edge knows, so the About panel must report whether WebAssembly runs and how long the module took to start. The probe of November 12 found neither condition on Damon's machine: it runs Chrome, and WebAssembly runs there at compiled speed (above).
- `sysml-v2-lsp` 0.42.0 (MIT, November 2026) is an ANTLR4 language server on a grammar pinned to the 2026-09 release, with a symbol table rather than SysML's scoping, and no browser packaging. SysIDE Editor Legacy (`sysml-2ls`, EPL-2.0, Langium, full scoping) is deprecated and archived at the 2024-12 release; its successor is free but not shown to be open source. `tree-sitter-sysml` 0.1.0 gives syntax only. `@memoarchitect/tools` (MIT) builds on OpenSysML and SysIDE and calls itself pre-stable.

**Licences.** Everything named above is MIT, Apache-2.0 or EPL-2.0 (elkjs 0.11.0 is EPL-2.0; the GPL alternative appears only from 0.12.0), and Roboto is under the Open Font License, all of which allow vendoring the files beside the page, on conditions the build must keep: a third-party notices file in the repository carrying every MIT and BSD notice, Apache-2.0's text for OpenSysML and EPL-2.0's text with the SysML v2 Release's copyright holders and a statement of where the sources are; the notices that esbuild's minifier strips put back; and elkjs shipped as its own unmodified file rather than merged into Grasp's bundle, since EPL-2.0 is defined file by file. OpenSysML's code is Apache-2.0, but the 94 standard library files inside its module are the SysML v2 Release's and EPL-2.0, as the module's own notice says, and its npm packages ship no licence or notice file, so the vendored module must carry that notice and the EPL-2.0 text beside it. The repository has no licence file of its own yet, and the EPL-2.0 question it already has for `SysML.ecore` now covers the module too; EPL-2.0 asks that changes to EPL-2.0 files, not the page around them, be made available.

**Claude's side.** esbuild, Playwright, Node and Java are available there, so the bundling, the tests and the pilot validator stay where they are today. The validator remains the authority on whether a text is SysML v2; OpenSysML's diagnostics in the page are the checks while drawing.

## The decisions

Three plans were drafted from different angles (the least work that meets the needs; SysON's look reproduced as faithfully as possible; the most continuity with Grasp's code), judged through three lenses (Damon's needs and constraints read literally; engineering risk and sequencing; the day-to-day loop) and merged. The needs-first draft won two of the three judges and the continuity-first draft the third; the plan below is the needs-first draft with what the judges asked it to take from the other two.

1. **Rebuild the page on vendored libraries; keep the model library.** The page's code, 6,659 lines of hand-written SVG renderer, layout, camera, pointer handling, panel markup and store, is replaced by a React application bundled by esbuild on Claude's side into classic scripts committed to git, which Damon downloads with the repository and opens from the extracted folder. The model library, 4,966 lines, stays whole and stitched by `build.mjs` into one classic script as today, so `export.mjs`, `check.sh`, the metamodel generator and the library's Node tests keep running unchanged through the first three slices; its model layer changes shape in the fourth, as decision 5 says, and what it knows about drawing, tools, labels and checks stays. Of the 39 test files, 33 drive the old page through Playwright and are replaced by tests of the new page; the 6 that run in Node stay. The new application is written in TypeScript, which esbuild strips, because the libraries it drives are typed; the model library stays plain JavaScript. Rejected: evolving the hand-written page under the 23 strategies, since the look is the thing libraries do best and most of the strategies were ways to make hand-written interface code extensible; and a shell without a widget library, since widgets, dialogs, menus, toasts and the tree are where the mature feel comes cheapest.

2. **React Flow for the diagrams.** SysON's own engine: one instance per tab, nodes as React components keyed by kind with compartment rows, `NodeResizer` for the resizing Damon asked for, parent nodes for nesting and view frames, connection handles whose `isValidConnection` is fed by Grasp's rules (`canContain`, `acrossDefinitions`), reconnection by dragging an end, marquee and Ctrl-click selection, snap, minimap and controls, only the visible nodes rendered. Edges are our components with SysML's arrowheads, labels and markers (composition diamonds are ours; React Flow ships only arrows). What the spike did not show and the checks did: React Flow's state is controlled by object identity, so Grasp's mutable model is projected into fresh node and edge objects after each change, with React Flow's own fields (measured sizes, selection, drag and resize state) merged back from a cache per view, and the history records only settled changes (a drag's end, a resize's end, add, remove); border ports are ours (their positions kept on the border as the box moves and resizes, the node told when a port changes side); frames need explicit sizes, precede their children in the list and do not clip them; editable rows opt out of dragging and of double-click zoom. Rejected: maxGraph, whose editor is richer but whose API changes between minor versions and whose nodes are shapes in its own terms; it stays the fallback if React Flow's lack of built-in routing and undo costs more than expected. JointJS, whose editor controls are in the paid tier.

3. **Dockview for the shell, Material UI for the widgets.** Dockview gives the editor area's tabs (which drag, split and float inside the window; popping a tab out into another window is refused from a page opened from disk), the side panels, the sashes and a saved layout; Material UI 7 gives the slim top bar that replaces the header, the right-click palettes as menus, dialogs, toasts, text fields, checkboxes, radios, reference pickers with chips, and the Core and Advanced tabs; MUI X Tree View's free edition gives the Explorer with keyboard navigation, selection and in-place renaming; its virtualization is in the paid edition, so a tree of thousands of elements starts collapsed at its roots or windows itself. A Tools view docked at the side lists the active view kind's creation tools, beside the right-click palettes, as decision 10 of the strategies document says. Roboto is vendored. Rejected: SysON's own three-zone arrangement with a hand-written tab bar, which gives less than Dockview for more code; plain DOM panels, which keep the old look.

4. **OpenSysML as the reader, the printer and the checker.** One of its modules, gzipped and embedded as base64 in a classic script, loaded lazily on the first import, insertion or check, never at page start, and run in a worker made from a Blob URL so that a parse never freezes the page, inline only if that worker fails. Its jobs: reading `.sysml` and `.kerml` text into the standard JSON element form, every element of every metaclass with its memberships, imports, typings and documentation; printing that form back as text; resolving names for typings, specializations and imports against the 94 standard libraries it bundles, with the members an element inherits; the specification's diagnostics, debounced into the Validation panel beside Grasp's own live rules; and seeding a view's contents from what it exposes. Which module: first choice, the full service built to WebAssembly by Claude from the Apache-2.0 sources, since it serves every operation (conversion both ways, queries, document rendering, source-preserving edits) over the typed client the spike already used; second, the published command-line build driven over an emulated terminal in the worker, which is how the conversions were run in this session; the typed module probed first serves only if neither works, and then import needs a syntax tree from elsewhere, the MIT ANTLR grammar of the 2026-09 release or a statement splitter of our own over the module's spans. The spike at the start of the text slice decides. The module is never the live model. Rejected: the hand-written parser the strategies document planned; SysIDE's archived parser, two spec releases behind; the ANTLR language server as the reader, since its symbol table is not SysML's scoping. Known from the probes of the typed module: its walked symbols carry no imports, documentation bodies, short names or source positions, skip anonymous elements such as comments and connector ends, and report coarse kinds (a transition walks as an action usage), while `renderView` gives file positions and finer kinds for what a view shows; `convert`, `renderDocument`, `query` and `applyEdits` are absent from it; a 5,021-symbol model parses in about 1.3 s and walks in about 2.4 s.

5. **An element graph with stable ids, in the standard form, stays the truth.** Format `grasp/3`: the model is the SysML v2 API's element form, an element per metaclass instance with the specification's property names, memberships, imports, typings, multiplicities, literals and documentation among them, with one difference from what OpenSysML writes: the ids are Grasp's own, assigned once when an element is made or first imported and kept for its life, where the converter derives ids from qualified names and so changes them at every rename. The hand-written kind rows of today's library become presentation only: how a metaclass is drawn, which tools make it, how its label reads. Notes keep their place as elements, as do code links. Each view's layout lives in a file of its own beside the model, so a drag never dirties the model's diff, and a `.sysml` twin is written at every save, so GitHub shows readable text next to the JSON. Text is read, never the only truth: ids have no home in SysML text, and every diagram edit would otherwise become a text edit, which is why SysON too keeps its graph as the truth. When a text file the page already holds is imported again, elements match by qualified name and metaclass, so ids and layouts survive. One format change, in one slice, with its upgrade and fixture as `src/README.md` prescribes. Rejected: text as the truth; two format changes (the look-first draft's); and Grasp's own shape of graph (kinds with `from` and `to` ends, the needs-first draft's), which would have needed a writer and an importer of our own for every metaclass, where the standard form gets both from OpenSysML. The risk taken instead is the converter's experimental status, held by the fallback in the next decision.

6. **OpenSysML prints; Grasp's writer stays as the cross-check until it is not needed.** The text of a model is OpenSysML's conversion of the element graph, in the page and in `export.mjs` on Claude's side through the same module in Node. Grasp's `toSysML`, which passes the pilot's validator and is pinned by nine fixtures, stays beside it through the text slice: every fixture must convert to text that `check.sh` accepts and that reads back to the same elements, and until every fixture does, the pinned writer is the authority for what text Grasp emits. If the converter's experimental status bites, if it refuses constructs Grasp needs or changes its vocabulary under us, the fallback is the needs-first draft's route: Grasp's writer grown metamodel-generic and the import's structure from a syntax tree of our own choosing. Rejected: writing the generic writer first, before knowing whether it is needed.

7. **A workspace folder, and GitHub as the carrier.** A workspace is a folder Damon picks once, remembered through its handle; it holds the workspace file (tabs, each a plane listing views from any model with their places and camera; the panel layout; the repository and branch), the model files with their `.sysml` twins, the view files and the notes. Where a policy blocks the File System Access API, a file input opens and a download saves; where a policy suppresses every file dialog, a download still saves and the conversation carries the files in. Files reach Claude through GitHub: Pull and Push in the page through the GitHub API with a fine-grained token Damon pastes once, held in this browser and never written to a file; Push compares each file with the branch and refuses on a mismatch, asking to Pull first; Claude works with git on its side; failing all of that, files pass through the conversation. The page's store on claude.ai, `model/working`, Download state and Import state go. An About panel reports what works on Damon's machine: the folder picker, the remembered handle, a request to the GitHub API, the browser's version.

8. **Code links as metadata into GitHub.** A code link is a metadata usage of a small bundled Grasp library, `metadata def CodeLink` with repository, path, ref, lines and language, owned by the element it realizes, exported as metadata and imported back as such; it shows as a row of the element's code compartment and as a Code section in Details with Open on GitHub and an excerpt fetched through the API. The code text leaves the model; the links in the Stronghold example migrate to links into the Stronghold repository. Claude writes the code, pushes it once Damon approves, and updates the ref. Rejected: textual representations holding permalinks, which misuse that construct; keeping code text in the model.

9. **Seven slices, in this order**, each one or more commits Damon reviews on GitHub and opens from the downloaded repository: the shell and the planes; editing parity, the old page retired one view kind at a time; the workspace folder and the loop through GitHub; every concept in the standard form, read and written through OpenSysML; text in the page; code links; the finish of the look. The three pains end in the first slice; the loop moves to files in the third, before the format changes, so that Claude's scripts keep working on the same files throughout; the format and the converter arrive together in the fourth, since each is what makes the other useful; nothing built early is thrown away later, because the node components are keyed by kind rows from the start, the history sits outside React, and the one adapter from the saved model to nodes is the single piece the format change replaces.

10. **What is dropped.** Of the 620 entries: the 10 "out" (SysON's server-published libraries) and the 100 "later", listed by name in `scope.md`, which wait for Damon's ask; also XMI and SysON JSON import, SysON's exact 169 tool placements and palette sections, its Query view, its collaboration features and its requirements table. Of the 23 strategies: tables as a mechanism and copy-and-paste dropped whole; the hand-written parser, the XMI and JSON readers, the library converter, the table of layout keys, the arrange folder, the dialog host at SysON's breadth and the command table at SysON's size dropped as parts. Of Grasp: the store layout, the published page and their tests.

## The slices

Each slice names what Damon gets, what it uses, and the check that says it is done.

1. **The shell and the planes.** The new page: a slim top bar in place of the header; Dockview with the Explorer (MUI X Tree View over the library's tree rows), the Tools view, Details (MUI widgets drawn from the `FIELDS` rows, committing through `edit()`) and Validation at the sides; the editor group holding one tab per view of the open model, each tab a React Flow plane showing the view's elements as SysML-style nodes with compartments and its lines as edges; sashes that resize and collapse; a selected box with resize handles whose new size is saved; drag, marquee and multi-select; one selection shared by every panel; right-click palettes from the view kind's tools; undo carried over from the Proxy history, with redo added; the Stronghold example and today's state files opened through the picker or a file input; the About panel. The saved format stays `grasp/2`, so the old page still reads every file. Uses: React 18, React Flow, Dockview, MUI, MUI X Tree View, esbuild; the build writes the third-party notices file and keeps elkjs as a file of its own. Done when: opened from the file system in Chromium with no console error, the example shows its general view on a tab, no header palette or button row exists, a sash drag resizes the Explorer, a box resized by its handles keeps its size after save and reload, each checked by a Playwright test from `file://`; the library's Node tests pass unchanged; a 5,000-element model opens and a drag step measured inside the handler stays under 16 ms, or the limit is restated with the measurement.

2. **Editing parity, the old page retired kind by kind.** Everything Damon does today, done the mature way: drag from a node's handles to draw any relationship the view kind allows, with a small menu when more than one kind fits; reconnect by dragging an end; label editing by typing with SysON's grammar, in nodes and in rows; checks while drawing, debounced, with badges and the Validation panel; refusals as toasts; Delete, F2, Escape; undo and redo over model and layout; all eight view kinds, as React Flow node and edge components where they fit and as SVG inside the tab where they fit worse (sequence and geometry are the doubtful ones), the grid as a table, the browser as the Explorer with chosen roots; notes pinned to nodes, edges and the plane, the archive, the code links section as today. Each kind retires its part of the old page once its fixture, its pinned export and its scale test pass on the new one; the old page is deleted when the last does. Done when: every fixture opens and, saved from the new page, exports its pinned text; the Playwright suite, rewritten for the new page, passes with the scale tests; `canvas/index.html` and the SVG renderer are gone.

3. **The workspace folder and the loop through GitHub.** Open folder; the workspace file, the model files with their `.sysml` twins, the view files, the notes; several views on one tab from any open model; New model from the empty editor's card; Save in place, with the file input and download fallbacks; Pull and Push through the GitHub API with the token and the mismatch check; the claude.ai store gone; Node scripts on Claude's side to validate a workspace, arrange a view with ELK, list what a view shows, export and check it; the loop section of `canvas/README.md` rewritten. Done when: a Playwright test with a stubbed picker opens a folder holding the workspace file and two models, moves a box, saves and reopens with the same places; in a session Claude pulls, moves two boxes by editing a view file, answers a note, pushes, and Damon's page pulls and shows both; Push on a stale file refuses.

4. **Every concept, in the standard form.** First the spike that picks the OpenSysML module (the full service built to WebAssembly, the command-line build over an emulated terminal, or the typed module with a syntax tree from elsewhere) and the round trip of every fixture and the pilot's examples through its conversion, counted by kind; then format `grasp/3` as decided: the standard element form with Grasp's ids, the kinds' rows reduced to presentation, the upgrade from `grasp/2` with a fixture that uses many metaclasses beyond today's kinds; import of `.sysml` and `.kerml` files through the conversion, new elements given ids and placed by ELK where a view exposes them, and export as the conversion back, with Grasp's writer kept as the cross-check decision 6 describes; a generic node with compartments by owned-member kind, a generic row with direct edit, a generic Details form (every attribute of the metaclass with a widget by type, references through pickers with candidates); the palette and the Tools view offering every kind a view admits, grouped by family. ## Decided for slice 1

Slice 1's plan, `plan/slice-1.md`, approved by Damon on November 12, 2026, settles what this document leaves open for the slice. In short, with the reasons in that plan's section 7:

- **Where the code lives.** The application is in `canvas/app/` (sources in `src/`, tests in `test/`, the build in `build.mjs`), with one `package.json` and its `package-lock.json` at the repository's root. `canvas/src/` stays the old build's.
- **Three classic scripts.** The build writes `model-lib.js` (the model library, the same text `export.mjs` runs), `vendor.js` (the libraries, on one global) and `app.js` (Grasp's own code) into `canvas/dist/`, which is committed.
- **Exact, locked versions.** Every package is pinned exactly and installed by `npm ci` from the lockfile.
- **Edge groups.** The side views sit in Dockview's edge groups, which resize by a sash and collapse to a strip.
- **Ports as child nodes.** A port is a React Flow node of its own, a child of its owner's node, which Grasp's code keeps on the border.
- **Stores outside React.** Each view's nodes and edges are kept in a store outside React, read through `useSyncExternalStore`.
- **What slice 1 draws.** The four graph view kinds (general, interconnection, action flow, state transition) with all 13 shapes; the other four kinds show a card until slice 2; no frame is drawn while a tab holds one view.
- **Saving.** Slice 1 saves the state file it opened, in `grasp/2`, through its handle or as a download, and remembers no file across a reload.
- **The look.** Grasp's ink and teal in SysON's proportions, light only, checked by assertions in tests and by screenshots that are looked at, not compared pixel by pixel.
- **Checks as tests.** The "Done when" checks are tests written first and marked todo, with their status in `plan/status.json`.
- **Four scale limits.** A 5,000-element model opens; a drag step under 16 ms; a keystroke in a name under 50 ms; a pan step of a fitted view under 16 ms. A limit that fails comes back to Damon with its measurement.

Damon's three choices: React Flow's mark is hidden on the planes and credited in About and the notices file; the theme is light only until slice 7; relationships are drawn by two clicks from the Tools view and the palettes in slice 1, and slice 2 adds drawing by handles.

One departure from "What was checked": Dockview is pinned at 8.9.0, not 8.8.3, for all three of its packages, because `dockview-react` 8.8.3 now installs the 8.9.0 core.

## Decided for slice 2

## The fourteen decisions of the strategies document, under the cut

1. **A plane per tab.** Stands. A tab is a Dockview panel holding one React Flow instance, whose view frames are parent nodes.
2. **A view on several tabs.** Stands: each tab keeps its own place for the frame.
3. **Any number of models per tab.** Stands.
4. **Models reference each other.** Stands, and gets easier: OpenSysML resolves names across every file of a workspace.
5. **A workspace file.** Stands: a folder on disk, picked once, holding the workspace file, the model files and the diagrams.
6. **Grasp runs only as a file.** Stands, and is now verified for the File System Access API, with a download and a file input as the fallback where a policy blocks it.
7. **Files are how Claude and Grasp exchange models.** Stands, with GitHub as the carrier: the page pushes and pulls through the GitHub API, Claude through git.
8. **All the standard libraries, read-only.** Stands, and comes for free: OpenSysML bundles the 94 library files of the 2026-09 release, byte for byte those of the 2026-09.1 release the validator uses; the page lists them read-only from the module's symbols instead of converting them ahead of time.
9. **Grasp reads SysML v2 itself, with a reader in the page.** Stands, with OpenSysML's module as the reader, and now the printer too, instead of a hand-written one; the pilot stays as the check on Claude's side.
10. **A Tools view at the side and right-click palettes.** Stands, as React components fed by one command table; the header palette and its buttons go.
11. **One shared selection.** Stands: React state that every panel and tab reads.
12. **Documentation and comments as elements.** Stands, as part of holding every metaclass.
13. **The format changes go ahead.** Stands, as one change instead of three: the saved model becomes the standard element form with Grasp's ids, upgraded from `grasp/2` as the format has always been upgraded.
14. **A one-person tool.** Stands.
